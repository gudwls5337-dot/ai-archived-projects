# 프로젝트 공통 작업 규칙

## 1. 한 번에 한 단계만 진행한다

- 하나의 작업이 완전히 끝난 후 다음으로 넘어간다
- 여러 파일을 한꺼번에 만들지 않는다
- 사용자가 확인했을 때만 다음 단계를 시작한다

---

## 2. 파일을 만들기 전에 반드시 역할을 먼저 설명한다

- 이 파일이 왜 필요한지
- 어떤 역할을 하는지
- 다른 파일과 어떤 관계인지

설명 없이 코드를 먼저 작성하지 않는다.

---

## 3. 새 파일과 수정 파일을 구분해서 안내한다

작업할 때마다 아래 형식으로 먼저 알린다.

- **새로 만드는 파일**: 파일명 + 역할 설명
- **기존에서 수정하는 파일**: 파일명 + 무엇을 왜 바꾸는지 설명

---

## 4. 단계가 끝나면 테스트 방법을 제시한다

- 코드가 제대로 작동하는지 확인하는 명령어를 알려준다
- 성공했을 때 어떤 결과가 나오는지 미리 설명한다
- 오류가 났을 때 어떻게 확인하는지도 알려준다

테스트 방법 없이 다음 단계로 넘어가지 않는다.

---

## 5. 초보자 기준으로 설명한다

- 개발 용어는 반드시 쉬운 말로 함께 설명한다
  - 예: "모듈(=기능 단위로 나눈 파일)"
- 명령어는 복사해서 바로 쓸 수 있게 코드 블록으로 제시한다
- 왜 이렇게 하는지 이유를 항상 먼저 설명한다
- 당연한 것도 생략하지 않는다
