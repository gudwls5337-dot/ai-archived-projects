# 🔍 YouTube Shorts Scraper - 작동 문제 원인 분석

## 📊 현황

### ✅ 잘 작동하는 것
1. **CLI 도구 (scraper.py)** - 완벽하게 작동
   - YouTube 채널에서 쇼츠 정보 추출 성공
   - Whisper 음성 인식으로 자막 추출 성공
   - CSV/JSON/XLSX 저장 성공

### ❌ 작동하지 않는 것
1. **FastAPI 웹 서버 (main.py)** - 포트 8001 바인딩 실패

---

## 🎯 작동되지 않았던 원인들

### 1️⃣ 포트 충돌 (Port Binding Conflict)
**문제:**
```
ERROR: [Errno 10048] error while attempting to bind on address ('0.0.0.0', 8001)
```

**원인:**
- 포트 8001이 이미 다른 프로세스(PID: 29896)에 의해 사용 중
- 이전에 실행한 FastAPI 서버가 여전히 메모리에 남아있음

**진단:**
```bash
netstat -ano | findstr ":8001"
# 결과: PID 29896이 포트 8001 점유
```

**해결 방안:**
```powershell
# 1. 프로세스 종료 (Windows)
taskkill /PID 29896 /F

# 2. 다른 포트로 실행 (main.py 수정)
uvicorn.run(app, host="0.0.0.0", port=8002)  # 8001 → 8002

# 3. 또는 main.py에 포트 설정 추가
python main.py --port 8002
```

---

### 2️⃣ requirements.txt 불일치 (Dependency Documentation)
**문제:**
```
requirements.txt에는 없지만, 코드에서 필요한 패키지:
- whisper          (main.py line 53)
- yt-dlp           (main.py line 69)
- openpyxl         (data/storage.py line 91)
```

**현재 requirements.txt:**
```
fastapi
uvicorn
google-api-python-client
google-auth-oauthlib
google-auth-httplib2
youtube-transcript-api
pydantic
python-dotenv
```

**왜 작동했는가?**
- 패키지들이 시스템에 이미 설치되어 있음
- 다른 프로젝트에서 설치한 것일 가능성

**문제점:**
- 새 개발자/새 환경에서는 `pip install -r requirements.txt` 후 바로 작동 안 됨
- 프로젝트의 진정한 의존성이 명시되지 않음

---

### 3️⃣ 엔트리 포인트 중복 (Multiple Entry Points)
**문제:**
- CLI와 웹 서버가 분리되어 있음
- 초기 사용자는 어느 것을 사용해야 할지 혼란
- main.py는 제대로 테스트되지 않은 상태

**현재 구조:**
```
scraper.py       → 명령줄 인터페이스 (작동 ✓)
main.py          → FastAPI 웹 서버 (포트 충돌로 미작동)
```

---

### 4️⃣ API 키 보안 문제
**문제:**
`.env` 파일에 실제 API 키가 평문으로 저장됨
```
YOUTUBE_API_KEY=AIzaSyB_7Y2fNdb4XdMZ8S9RHhkjvRh8n8H7u7U
```

**위험:**
- Git 리포지토리에 실수로 커밋될 수 있음
- 개인 API 할당량 노출 (일일 10,000 units)
- 다른 사람이 API 키 악용 가능

**진단:**
```bash
git log --all -S "AIzaSyB_7Y2fNdb4XdMZ8S9RHhkjvRh8n8H7u7U"
# 커밋 히스토리에 노출되었는지 확인
```

---

### 5️⃣ Whisper 성능 경고
**증상:**
```
UserWarning: FP16 is not supported on CPU; using FP32 instead
```

**원인:**
- CPU가 FP16(Half Precision) 연산 미지원
- FP32(Full Precision)로 자동 전환됨

**영향:**
- 처리 속도 약간 저하
- 메모리 사용량 증가
- 정확도는 동일

| 번호 | 문제 | 심각도 | 원인 | 해결 상태 |
|------|------|--------|------|----------|
| 1 | 포트 8001 충돌 | 🔴 높음 | 프로세스 점유 | taskkill 필요 |

| 5 | Whisper 경고 | 🟢 낮음 | 하드웨어 제약 | 무시 가능 |

## ✅ 권장 해결 순서

### 1단계: 긴급 (보안)
```bash
# API 키 재발급
# .gitignore에 .env 추가
# .env 파일 히스토리에서 제거
git filter-branch --tree-filter 'rm -f .env' -- --all
```

### 2단계: 필수 (작동)
```bash
# requirements.txt 업데이트
pip freeze > requirements.txt

# 또는 수동으로 추가
# whisper, yt-dlp, openpyxl
```

### 3단계: 권장 (유지보수성)
```bash
# 포트 충돌 해결
taskkill /PID 29896 /F

# 또는 main.py를 더 견고하게 수정
# → 포트 설정을 config.py로 옮기기
```

## 📌 결론

이 프로젝트의 **기본 기능은 정상**입니다. (scraper.py 테스트 완료)

다만 다음 3가지가 초기 사용자의 작동을 방해했습니다:
1. **포트 충돌** - 일회성 문제
2. **문서화 누락** - requirements.txt 불완전
3. **보안 누수** - API 키 노출

이 세 가지를 수정하면 완벽하게 작동할 것입니다.
